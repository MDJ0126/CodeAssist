시작하기

설치와 시작

• CodeAssist는 Visual Studio의 범용 C/C++ 개발 보조 확장입니다.

• VSIX를 설치하고 Visual Studio를 다시 시작하면 사용하실 수 있습니다.

• Unreal 프로젝트에도 사용할 수 있습니다.

도구 모음 사용

• 도구 모음 첫 번째 바나나는 설정, 두 번째 버튼은 파일 열기입니다.

• Welcome은 도구 모음 맨 뒤 또는 Tools → CodeAssist: Welcome에서 여세요.

설치본에 포함된 도움말

• 이 도움말은 설치 파일에 포함되어 Visual Studio 내부에서 열립니다.

• 저장소 다운로드, 웹사이트 또는 인터넷 연결이 필요하지 않습니다.

Getting started

Install and start

• CodeAssist is a general C/C++ extension for Visual Studio.

• Install the VSIX and restart Visual Studio.

• Unreal projects are also supported.

Using the toolbar

• The first toolbar banana opens Options.

• The second button opens files.

• Open Welcome with the last toolbar button or Tools → CodeAssist: Welcome.

Included offline help

• This help is included in the installer and opens inside Visual Studio.

• No repository download, website, or internet connection is required.

기능 사용

사용할 수 있는 기능

파일·심볼 찾기, 정의/구현 이동, 참조 검색, 파일 내 메서드 탐색, 대응 파일 열기, 자동 완성, 심볼 색상, 스니펫, 클립보드 기록을 사용할 수 있습니다.

표시 언어 변경

• 언어를 바꾸려면 설정의 Language에서 한국어 또는 English를 선택하고 저장하세요.

• 이미 열린 Welcome은 닫고 다시 열면 바뀐 언어로 표시됩니다.

Using features

Available features

Use file and symbol search, definition navigation, references, method navigation, corresponding files, completion, symbol colors, snippets, and clipboard history.

Change the display language

• Select Korean or English under Language in Options and save.

• Close and reopen an existing Welcome page to use the new language.

파일·심볼·참조 탐색

파일·심볼 검색

• Alt+Shift+O는 파일 찾기, Alt+Shift+S는 심볼 찾기입니다.

• 검색어를 입력하고 목록에서 항목을 선택한 다음 Enter를 누르세요.

정의·참조·메서드 이동

• Alt+G는 정의/구현, Alt+Shift+F는 참조, Alt+O는 대응하는 헤더/소스, Alt+M은 현재 파일 메서드 목록입니다.

• 검색 결과의 파일 경로와 위치를 확인하세요.

컴파일러 기반 탐색 준비

• 정확한 컴파일러 탐색에는 프로젝트에 맞는 compile_commands.json 또는 compile_flags.txt와 clangd 구성이 필요합니다.

• 구성이 없는 경우 인덱스 기반 후보와 VS 기본 기능을 사용합니다.

소스 링크 설정

• 소스 링크: 설정 → Navigation → Source Links에서 단순 패턴(issue #{id}) 또는 정규식(BUG-(?<id>[0-9]+))과 대상 URL을 추가하고 저장하세요.

• 주석의 일치 부분에 커서를 두고 CodeAssist: Open Source Link를 실행합니다.

• GitHub·FogBugz 예제의 사이트 주소는 직접 바꾸세요.

File, symbol, and reference navigation

Search files and symbols

• Alt+Shift+O opens file search; Alt+Shift+S opens symbol search.

• Enter a query, select a result, and press Enter.

Definitions, references, and methods

• Alt+G navigates to a definition, Alt+Shift+F finds references, Alt+O opens the corresponding header/source, and Alt+M lists methods.

• Check the returned file and location.

Compiler navigation setup

• Compiler navigation requires a matching compile_commands.json or compile_flags.txt and clangd configuration.

• Otherwise indexed candidates and Visual Studio commands are used.

Configure source links

• Source Links: add and save a simple issue #{id} pattern or a regex with named captures in Navigation / Source Links.

• Place the caret in a match and run CodeAssist: Open Source Link.

• Replace the placeholder host and repository in GitHub/FogBugz examples.

추천 목록과 코드 색상

코드 색상 변경

• 설정 → Editor → Coloring에서 향상된 심볼 색상과 타입·변수·함수·매크로 색상을 조정합니다.

• 저장하면 열린 문서에 적용됩니다.

추천 목록의 색상

• Visual Studio 기본 추천 색상 사용을 켜면 추천 목록에 적용하는 CodeAssist 전경색을 해제합니다.

• 코드 편집기 심볼 팔레트는 별도 설정입니다.

편집기 강조와 완성 설정

• Editor → Guides에서 현재 줄, 괄호 짝·불일치, 컬럼 기준선과 위치를 설정합니다.

• 머리글자 약어와 축약어 완성은 Editor에서 각각 끌 수 있습니다.

• 원본 VA의 기본값과 같은지는 미검증입니다.

Completion and code colors

Change code colors

• Open Options → Editor → Coloring to adjust enhanced symbol colors for types, variables, functions, and macros.

• Save to apply to open documents.

Completion list colors

• Enable Use Visual Studio completion colors to remove CodeAssist foreground overrides from completion lists.

• The editor symbol palette is a separate setting.

Editor highlights and completion

• Editor / Guides controls current-line, brace matching/mismatches and column guides.

• Editor toggles acronym and shorthand completion separately.

• Defaults have not been verified against VA.

선택·주석·괄호 편집

편집 동작 설정

Editor에서 주석 이어쓰기, 선택 영역 감싸기, 괄호·따옴표 자동 닫기, 닫는 중괄호 위치와 함수 괄호 간격을 설정합니다.

선택 영역 편집

• 선택 영역에 / 또는 *를 입력하면 주석으로, ( 또는 {를 입력하면 괄호로 감쌉니다.

• Smart Select의 Alt+Shift+]로 확장하고 Alt+Shift+[로 축소합니다.

Visual Studio 설정과의 관계

• VS 기본 괄호 기능과 함께 동작합니다.

• CodeAssist의 옵션을 끄더라도 VS 자체 기능은 VS 설정에 따릅니다.

스니펫과 파일 작업

• 선택 영역에서 스니펫을 만들면 솔루션의 .codeassist/snippets.tpl에 저장됩니다.

• 단축어를 입력하고 추천 목록이 닫힌 상태에서 Tab을 누르면 확장합니다.

• 사용자 입력 자리가 있으면 입력 창이 열립니다.

• 선택 영역을 새 파일로 이동하면 원본 편집은 Undo할 수 있지만 새 파일은 남습니다.

• 파일 이름 변경은 프로젝트 항목 이름만 바꾸며 include 참조를 자동 수정하지 않습니다.

리팩터링 지원 범위

• 추가 리팩터링: 서명 변경은 컴파일러가 찾은 선언·정의·호출부의 매개변수 순서를 변경합니다.

• 인수 추가·삭제·타입 변경은 아직 지원하지 않습니다.

• 포인터↔인스턴스는 지역 변수의 멤버 접근만 지원하며, 메서드 추출은 전역 void 함수와 명시 참조 매개변수만 지원합니다.

• 일괄 구현 이동은 기존 대응 소스 파일이 필요합니다.

• 도구 메뉴의 각 명령에서 변경 미리보기를 확인한 후 적용하세요.

Selections, comments, and pairs

Configure editing behavior

Configure comment continuation, surround selection, bracket/quote completion, closing brace placement, and function call spacing under Editor.

Edit selections

• Type / or * over a selection to comment it; type ( or { to surround it.

• Alt+Shift+] expands Smart Select and Alt+Shift+[ shrinks it.

Visual Studio settings

• Works alongside Visual Studio pair completion.

• Disabling a CodeAssist option leaves Visual Studio native behavior controlled by its own settings.

Snippets and file operations

• Create from Selection stores snippets in the solution .codeassist/snippets.tpl.

• Type a shortcut and press Tab with completion closed to expand it; variable fields open an input dialog.

• Moving a selection to a new file supports source Undo, while the new file remains.

• Rename File changes the project item name; include references are not rewritten.

Refactoring support

• Additional refactorings: Change Signature reorders compiler-resolved declarations, definitions and call arguments; adding/removing arguments and changing types remain unsupported.

• Pointer/instance conversion supports local member-access uses.

• Extract Method supports global void helpers with explicit parameters.

• Batch outline requires existing counterpart source files.

• Review changes before applying.

코드 검사

검사 모드 선택

• 상단 Enable은 프로젝트 기본 구문 검사를 시작하고 오류 목록에 후보를 표시합니다.

• Disable은 CodeAssist 검사를 끄며 Use per-file engine은 열린 파일별 검사를 사용합니다.

결과 확인

• 이 검사는 전체 컴파일러 진단이나 VA의 모든 검사기와 동일하지 않습니다.

• 빌드 오류와 함께 확인하세요.

Code inspection

Choose an inspection mode

• Enable on the top bar starts basic project syntax checks and reports candidates in Error List.

• Disable turns off CodeAssist checks; Use per-file engine selects open-file checks.

Review results

• These checks do not replace compiler diagnostics or the full VA inspection engine.

• Review them alongside build errors.

1. Open Tools → Options → Environment → Keyboard in Visual Studio.

설치·문제 해결

설치 확인

• VSIX 설치 후 이전 화면이 보이면 모든 Visual Studio 창을 닫고 다시 실행하세요.

• 확장 관리자에서 설치된 CodeAssist 버전을 확인할 수 있습니다.

다른 확장과 분리해 테스트

• CodeAssist만 테스트할 때는 VA 등 같은 기능의 확장을 비활성화하면 동작을 구분하기 쉽습니다.

• 문서나 테스트 파일의 변경 내용은 먼저 저장하세요.

설정·진단 파일 위치

• 설정은 사용자 LocalAppData/CodeAssist/startup.xml, Welcome 진단은 같은 폴더의 Welcome-host.log에 저장됩니다.

• 문제를 신고할 때 버전과 재현 절차를 함께 남겨 주세요.

성능 설정

• 고급 → 성능에서 파서 스레드 수를 조정합니다.

• 변경값은 다음 인덱스 빌드와 작업자 프로세스에 적용됩니다.

• 이미 실행 중인 작업의 스레드 수는 바뀌지 않습니다.

Installation and troubleshooting

Check installation

• If old UI remains after VSIX installation, close all Visual Studio windows and restart.

• Check the installed CodeAssist version in Extension Manager.

Isolate other extensions

• Disable overlapping extensions such as VA when isolating CodeAssist behavior.

• Save document and fixture changes first.

Settings and diagnostics

• Settings are stored in user LocalAppData/CodeAssist/startup.xml.

• Welcome diagnostics are in Welcome-host.log in the same folder.

• Include the version and reproduction steps when reporting an issue.

Performance settings

• Adjust parser threads in Advanced → Performance.

• The limit applies to the next index build and worker process.

• Running builds keep their current limit.
