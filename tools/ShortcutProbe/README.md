# ShortcutProbe
Standalone x64 .NET Framework diagnostic. Uses OS SendInput, DTE BeforeExecute events and screenshots. Does not call commands as a substitute for keys. Use only while the user has authorized desktop control. Arguments: target PID, report label, output folder, keyboard-analysis.json. Report label does not enforce extension isolation; verify actual command GUIDs. A successful injection is not functional parity. Current cleanup closes secondary test windows, so use a dedicated fixture VS. COM busy errors and missing events remain unresolved tests. Do not treat them as passes.

Build with Framework64 csc.exe referencing EnvDTE.dll, System.Windows.Forms.dll, System.Drawing.dll, System.Web.Extensions.dll. Run on an idle desktop with no held modifier keys. Foreground PID is checked before every injection. The generated fixture files are owned by this test; user source files are not edited.

## Actual result comparison
Run `./tools/ShortcutProbe/RunBehavior.ps1 -TargetProcessId <dedicated VS PID>` from the repository. The program checks editor focus, injects real OS keys, compares full buffer/caret/selection with four archived actual VA outputs, and compares requested Undo. It checks the SHA256 of VA evidence and rejects changed or invalid expected outputs. Before/after/Undo screenshots and JSON are retained. Eight adversarial comparator checks reject text, caret and selection differences, null and missing snapshots. A failed case makes the wrapper fail; matching no-ops, command receipt and screenshots alone are not passes. Requires an already initialized dedicated VS instance with CA loaded; it does not install or close user VS. Plan scope is four samples, not 108 features. `behavior-bindings-restored.json` must be inspected after each run. Preserve the source VA evidence referenced by behavior-plan.json.
